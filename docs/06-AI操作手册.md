# AI 操作手册（MCP / Claude Code 直读均适用）

本手册面向 AI 助手（经 MCP server 或直接读写 API/数据库）操作 IPD 工具箱时的约定速查。

## 1. 认证与 API 约定

- 认证：`Authorization: Bearer <token>`。长效 token（365 天）：登录后 `POST /api/auth/api-token`。
- 统一响应：`{code, message, data}`；`code=0` 成功。业务错误走 HTTP 200 + code：
  - `4000` 通用业务错误、`4010` 未登录、`4030` 无权限、`4040` 不存在
  - `4091` 非法状态流转；守卫拦截返回 `GUARD_*` 前缀 message（如 `GUARD_READY_UNMET`、`GUARD_REDLINE_UNMET`）
- 权限：Service 层按角色校验（PM/QA/REVIEWER/ADMIN 等 7 角色；ADMIN 兼全部）。

## 2. 核心对象与表速查

| 对象 | 表 | 说明 |
|---|---|---|
| 项目 | project | code 是编号前缀（如 OVN1）；lifecycle_status: ACTIVE/ON_HOLD/CLOSED |
| 工作项 | work_item | 单表 7 类型：CAPABILITY/REQUIREMENT/STORY/TASK/DEFECT/RISK/CHANGE；树结构靠 trace_link 的 parent_of，不靠 parent 列 |
| 追溯 | trace_link | source/target(type,id) + relation（10 种，见 §4） |
| 版本 | product_version | plan_release_date / actual_release_date（V9） |
| 阶段/DCP | stage_gate | plan_date / forecast_date（V9）；实际评审日 = decision.decided_at |
| 准入/准备度条件 | gate_criterion | is_redline 红线；is_readiness=1 为五领域准备度项；status: PENDING/MET/PARTIAL/NOT_READY/WAIVED |
| 决策 | decision | **只增不改**，修订走新记录 prev_decision_id；snapshot 列固化评审时准备度快照 |
| 证据 | evidence | 文件落本地 + SHA-256；category: EVIDENCE（正式，EV 编号）/ ATTACHMENT（描述附件截图，AT- 码） |
| 迭代 | iteration | start_date/end_date/status(PLANNING/ACTIVE/DONE/CLOSED)/hidden |
| 测试 | test_case / test_run | 用例 verifies 需求；执行 FAIL 可一键生成缺陷（自动 3 条追溯链） |

编号规则：`{项目code}-{类型缩写}-{三位序号}`，如 `OVN1-REQ-001`（code_seq 表行锁并发安全）。

## 3. 状态机（后端唯一权威，先查 next-statuses 再流转）

- 通用链（能力/需求/故事/任务）：Backlog → Ready → In Progress → Verification → Accepted
- 缺陷：Open → Analysing → Fixing → Retesting → Closed（**关闭前守卫要求复测 PASS**）
- 变更：Submitted → Impact Analysed → Approved/Rejected → Implemented → Verified（**审批前守卫要求影响分析完成**，ext_fields.impactAnalysed）
- 风险：Open → Mitigating → Closed/Accepted
- 回退（去往历史出现过的状态）必须携带 reason。

## 4. 追溯关系（trace_link.relation）

`contributes_to`（贡献于商业目标）、`parent_of`（分解）、`implements`、`verifies`、`blocks`、`depends_on`、`changes`（变更涉及）、`affects`、`evidences`、`released_in`

## 5. ext_fields 键约定（JSON 列，整串覆盖式更新，改前先读）

| 类型 | 键 | 含义 |
|---|---|---|
| RISK | `mitigation` | 处置措施 |
| RISK | `dueDate` | 处置期限 yyyy-MM-dd（超期预警/效能口径都读它） |
| RISK | `probability` / `impact` | 概率/影响 1~5；敞口=p×i 读时计算（高≥15/中≥8） |
| RISK | `strategy` | 应对策略 AVOID/TRANSFER/MITIGATE/ACCEPT |
| CHANGE | `impactAnalysed` | 影响分析完成标志（由 POST /changes/{id}/analyze 写入，勿手工设置） |
| 能力/需求/故事 | `wsjf` | {bv,tc,rr,size} 四因子（1~10），分=(bv+tc+rr)/size |

**风险任务化约定**：`POST /api/risks/{id}/mitigation-task` 按 mitigation 生成应对 TASK 并建
`TASK -affects→ RISK` 链（不设 mitigates 关系；(TASK, affects, RISK) 三元组即应对任务的精确识别）。

## 6. MCP 工具与 dry-run 约定

- 读 12：list_projects / get_project_brief / list_work_items / get_work_item / search_work_items / get_dcp_overview / get_readiness / list_alerts / list_decisions / **get_baseline_diff**（范围蔓延与偏差）/ **get_critical_path**（CPM 关键链）/ **list_lessons**（跨项目经验检索）
- 写 4：create_work_items / transition_work_item / update_work_item / create_trace_link
- **create_work_items 默认 dry_run=true**：先展示预览清单给用户确认，再以 dryRun:false 落库。逐条返回成败（BatchItemResult）。
- 决策类动作（DCP 评审 POST /dcp/gates/{id}/review、变更审批 POST /changes/{id}/decide）**不经 AI 执行**，请引导用户在 UI 完成。

## 7. 常用 REST 端点速查（完整见 /swagger-ui.html）

```
GET  /api/projects                         GET  /api/work-items?projectId&type
GET  /api/work-items/{id}/traces           GET  /api/work-items/{id}/next-statuses
POST /api/work-items/batch                 POST /api/work-items/batch-create   (dryRun)
POST /api/work-items/{id}/transition       PUT  /api/work-items/{id}
GET  /api/stage-gates?projectId            GET  /api/product-versions?projectId
GET  /api/dcp/gates/{gateId}/overview      GET  /api/readiness/summary?projectId
GET  /api/alerts?projectId                 GET  /api/decisions?projectId
GET  /api/metrics/overview?projectId       GET  /api/my/today
POST /api/traces                           POST /api/evidence (multipart, category=ATTACHMENT 可选)
GET  /api/baselines?projectId              GET  /api/baselines/{id}/diff     POST /api/baselines
GET  /api/schedule/critical-path?projectId POST /api/risks/{id}/mitigation-task
GET  /api/assets/lessons                   POST /api/assets/lessons          GET /api/assets/risk-patterns
GET  /api/projects/{id}/closeout-check     GET  /api/projects/{id}/weekly?days=
GET  /api/iterations/{id}/retro            GET  /api/gate-criteria/templates POST /api/gate-criteria/apply-template
GET  /api/timemachine/timeline?projectId   GET  /api/timemachine/as-of?projectId&date=yyyy-MM-dd
GET  /api/timemachine/compare?projectId&from=&to=
```

**时光机约定**：`as-of` 返回 date 当天收盘时的状态重建（回放 work_item_status_log，含已逻辑删除项，
状态与存在性维度精确；字段值历史不承诺）；`compare` 返回 A→B 期间每项的结论
（NEW/COMPLETED/CHANGED/UNCHANGED）+ KPI 双时点 + 期间决策/基线。适合回答
"DCP 评审前我们处于什么状态""上次承诺以来推进了什么"。

**基线约定**：DCP 评审 PASS/CONDITIONAL 时自动固化范围基线（B-{gateCode}，关联决策）；
基线只增不删，明细为冻结值；diff 的 ADDED=范围蔓延、slipDays=forecastDate−冻结计划日。

## 8. 典型对话剧本

**剧本 A：会议纪要拆条**
1. 用户粘贴纪要：「本次评审确定三件事：① 增加低噪模式（需求）② 风道仿真本周完成（任务）③ 电机供应商单一是风险，月底前引入二供」
2. AI 调 `create_work_items`（dry_run=true）→ 返回预览：REQUIREMENT「低噪模式」、TASK「风道仿真」、RISK「电机供应商单一」
3. 用户确认 → AI 以 dryRun:false 重调 → 返回三条编号；风险再用 `update_work_item` 补 ext（或提示用户在治理页补处置期限）。

**剧本 B：DCP 评审材料**
1. 用户：「帮我整理 OVN1 DCP2 的评审材料」
2. AI：`list_projects` 定位项目 → `get_project_brief` → `get_dcp_overview(gateId)` + `get_readiness` + `list_decisions`
3. 汇编：准备度快照、红线清单（含未满足项及证据数）、五领域满足率、历史决策链、遗留承诺，输出 Markdown 文档；提醒用户正式评审在 UI「发起 DCP 评审」完成（或直接打开 /report/dcp/{gateId}?projectId= 打印决策包）。
