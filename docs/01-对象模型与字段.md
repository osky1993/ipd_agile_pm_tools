# 最小业务对象清单与字段（阶段0 · T002）

> 驱动 Flyway `V1__schema.sql`。字段类型以 MySQL 8 为准。编号规则：`{项目代码}-{类型缩写}-{三位序号}`，如 `OVN1-REQ-001`。

## 通用必备字段（规划§5.4，落在 work_item 及关键对象上）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | BIGINT PK 自增 | 是 | 内部主键 |
| code | VARCHAR(32) 唯一 | 是 | 业务编号，按项目+类型生成 |
| project_id | BIGINT | 是 | 所属项目 |
| product_version_id | BIGINT | 否 | 所属产品版本 |
| title | VARCHAR(255) | 是 | 标题 |
| description | TEXT | 否 | 说明 |
| status | VARCHAR(32) | 是 | 当前状态（受状态机约束） |
| owner_id | BIGINT | 否 | 责任人 |
| priority | VARCHAR(16) | 否 | P0/P1/P2/P3 |
| baseline_date | DATE | 否 | 基线日期 |
| forecast_date | DATE | 否 | 最新预测日期 |
| acceptance_criteria | TEXT | 否 | 验收条件 |
| created_by / created_at | BIGINT / DATETIME | 是 | 创建人/时间 |
| updated_by / updated_at | BIGINT / DATETIME | 是 | 最后修改人/时间 |
| deleted | TINYINT | 是 | 软删除标记，默认0 |

### work_item.type 取值（类型缩写用于编号）

| type | 缩写 | 状态机 |
|---|---|---|
| CAPABILITY | CAP | 通用工作项流 |
| REQUIREMENT | REQ | 通用工作项流 |
| STORY | STO | 通用工作项流 |
| TASK | TSK | 通用工作项流 |

## 演进补充（第一版后新增对象，2026-08）

阶段0 契约的 12 张核心表结构未变；后续演进按需增表（Flyway V4~V13），语义补充如下：

| 表 | 迁移 | 说明 |
|---|---|---|
| metric_snapshot / perf_snapshot | V4 / V7 | 指标每日快照（宽表 / 长表），读取时对当天 upsert |
| iteration_commitment | V7 | 迭代承诺快照：拉入即承诺、移出不减（承诺完成率与复盘的分母） |
| baseline / baseline_item | V11 | **范围基线**：DCP 通过（PASS/CONDITIONAL）自动固化需求域清单（CAPABILITY/REQUIREMENT/STORY），明细列全部冻结，只增不删；diff 输出蔓延/移除/完成/日期偏差/估算漂移 |
| lesson | V13 | **经验教训**（组织资产）：类别 WELL/IMPROVE/PROCESS/TECH/SUPPLY/OTHER，可关联来源（WORK_ITEM/DECISION/ITERATION），跨项目检索 |

`ext_fields` 键约定演进（完整清单见 [06-AI操作手册.md](./06-AI操作手册.md)）：

- RISK：`mitigation` / `dueDate` / **`probability`(1-5)** / **`impact`(1-5)** / **`strategy`(AVOID/TRANSFER/MITIGATE/ACCEPT)**——敞口 = p×i 读时计算（高≥15/中≥8）；
- 能力/需求/故事：**`wsjf`** = {bv, tc, rr, size}（各 1~10），分 = (bv+tc+rr)/size；
- 决策修订链：`decision.prev_decision_id` 由 DecisionService 自动串接（V12 已回填历史），同 subject 的历史决策可沿链回放。

追溯关系语义补充：**(TASK, affects, RISK)** 三元组表示"风险应对任务"（由风险任务化功能生成，不另设 mitigates 关系）。
