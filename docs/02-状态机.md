# 状态机清单（阶段0 · T003）

> 驱动状态机引擎（T205）与 5 条守卫（T303/T308/T309/T307/T401）。守卫失败统一返回结构化错误码，前端统一提示。

## 1. 通用工作项（CAPABILITY/REQUIREMENT/STORY/TASK）

```
Backlog → Ready → In Progress → Verification → Accepted
```

| 迁移 | 进入条件（守卫） | 退出/回退 |
|---|---|---|
| Backlog→Ready | 有验收条件、有责任人、有估算（守卫#1 Ready） | 可回退 Backlog（填理由） |
| Ready→In Progress | 已进入某 Sprint 承诺 | 可回退 Ready |
| In Progress→Verification | 必须关联可验证版本或证据（守卫#3） | 可回退 In Progress |
| Verification→Accepted | 记录验收人+时间，语义=业务/能力验收（守卫#4） | 可回退 Verification（失败复检） |

## 2. 缺陷（DEFECT）

```
Open → Analysing → Fixing → Retesting → Closed
```

| 迁移 | 进入条件 |
|---|---|
| Retesting→Closed | 必须存在 result=PASS 的 TestRun（守卫#2） |

## 3. 变更（CHANGE）

```
Submitted → Impact Analysed → Approved/Rejected → Implemented → Verified
```

| 迁移 | 进入条件 |
|---|---|
| Submitted→Impact Analysed | 完成影响分析（按 TraceLink 列出受影响需求/测试/版本/DCP并人工确认）（守卫#5） |
| Impact Analysed→Approved/Rejected | 由授权角色决策，生成 Decision |

## 4. 风险（RISK）

```
Open → Mitigating → Closed
              └────→ Accepted（接受风险，需授权）
```

## 5. DCP 评审结论（gate_criterion.review_conclusion / decision）

`通过 PASS` / `有条件通过 CONDITIONAL` / `不通过 REJECT`

规则（规划§7.3，落 T502）：
- 红线（is_redline=1）未满足 → 不可判 PASS；
- status=已满足 但无 evidence → 标记"证据缺失"；
- status=豁免 → 必填授权人/理由/期限/补救；
- CONDITIONAL → 强制绑定遗留风险+责任人+期限；
- Decision 只增不改，修订=新记录 link prev_decision_id。

## 守卫错误码约定

| 码 | 含义 |
|---|---|
| GUARD_READY_UNMET | 未达 Ready 条件 |
| GUARD_VERIFICATION_NO_EVIDENCE | 进入 Verification 缺版本/证据 |
| GUARD_ACCEPT_NO_ACCEPTOR | Accepted 缺验收人/时间 |
| GUARD_DEFECT_NO_RETEST | 缺陷关闭无复测通过 |
| GUARD_CHANGE_NO_IMPACT | 变更未做影响分析 |
| GUARD_REDLINE_UNMET | 红线未满足不可判通过 |
